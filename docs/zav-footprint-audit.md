# ZAV 실제 외형·충돌체·팽창 여유 점검

사용자가 제공한 실물 치수는 408×408×245.5mm다. 현재 USD의 593개 메시와 346,102개 고유 정점을 직접 변환해 측정했다. [측정과 시험 기록](validation/zav-footprint-20261105/README.md).

| 항목 | 측정/기존 값 | 해석 |
|---|---:|---|
| USD 외형 | 407.978×407.978×244.636mm | 실물 치수와 거의 일치 |
| body 원점 기준 최대 수평 반경 | 244.947mm | 폭의 절반 204mm보다 대각 방향이 멀다 |
| 기존 충돌 원통 | R270×H250mm | 수평 반경 약 25.05mm, 높이 약 5.36mm 여유 |
| 실제 메시의 IMU 기준 외접구 | R351.018mm | IMU 오프셋을 포함한 값 |
| 기존 원통의 IMU 기준 외접구 | 약 R403.532mm | 실제로 없는 빈 공간도 채운다 |
| 새 외형 충돌체의 IMU 기준 외접구 | R355.322mm | 전체 메시 정점을 포함하는 64-vertex 외접 다면체 |
| 기존 계획 반경 | IMU 기준 R430mm | body 원점의 반경과 구분해야 한다 |
| 기존 팽창 | 격자 0.2m, 3칸 = 명목 0.6m | dense의 좁은 통로를 많이 제거 |

실제 외형의 최소 convex hull 부피는 0.019676m³, 기존 원통은 0.057256m³로 약 2.91배다. 새 물리 충돌체는 34개 지지 평면으로 만들었으며 부피 0.025588m³다. PhysX의 기본 64-vertex 제한 안에 들어가도록 모든 실제 정점을 **바깥에서** 감싼다. USD 원본과 1.99kg 질량·명시된 관성은 바꾸지 않는다. 센서 위치도 그대로다.

기존 비교를 재현할 수 있도록 원통과 기존 플래너 프로파일은 기본값으로 보존한다. 실측 외형 옵션은 다음과 같다.

```bash
./scripts/run_zav_forest.sh dense mid360 hull
```

캐시가 없으면 `./scripts/prepare_zav_vehicle_hull.sh`가 Isaac의 USD 라이브러리로 형상을 측정·생성한다. 실행 시에도 모든 실제 메시 정점이 이 충돌체 안에 있는지 확인한다.

## 팽창 비교

원래 dense 점군을 읽는 **오프라인** ROG-Map 진단을 별도 ROS domain에서 실행했다. 이 전체 점군을 실제 비행 플래너에 주입하지 않았다. 동일한 0.8~2.4m 높이 구간과 13×108m 조회 영역에서 비점유 격자 수는 기존 862,942개, 세밀한 0.5m 설정 1,246,589개였다(약 44.5% 증가). 6방향 격자 연결성도 달라졌다. 실제 A*는 대각 이동을 사용하고 부분 관측 지도에서 탐색하므로 이 진단이 곧 임무 성공을 증명하지 않는다.

단일 장애물 주변을 0.1m 격자점으로 표본 검사했을 때 최소 자유 중심 거리는 기존과 세밀한 0.5m 설정 모두 약 0.510m였다. 명목 팽창값을 0.6→0.5m로 바꾸는 동시에 격자 해상도를 0.2→0.1m로 바꿔, 거친 격자가 방향에 따라 더 많이 막던 공간을 줄이는 비교다. 반경 0.43m는 유지한다. 0.4m 설정의 표본 최소 거리는 약 0.412m로 0.43m보다 작아 현재 계획 반경과 그대로 조합하지 않는다.

실험용 플래너 명령:

```bash
./scripts/run_zav_forest_planner.sh dense 1 --fine-inflation
```

ROG가 팽창 격자 설정으로 가상 바닥·천장까지 이동시키므로 raw 높이 값도 보정한다. 실제 회랑 생성에 쓰이는 plane은 이전과 동일한 LIO frame z=-0.1/3.3m다(차량 중심용 반경 축소 적용 전). 생성 파일은 `planner-1-fine05.yaml`이며 기존 `planner-1.yaml`은 그대로 남는다.

나머지는 기존 FAST-LIVO와 OMMPC 실행을 사용한다. dense OMMPC는 `./scripts/run_zav_ommpc.sh -p max_yaw_rate:=1.0`, 임무는 `./scripts/run_zav_forest_mission.sh dense --controller ommpc --goal-timeout 180 --timeout 500`이다. 별도 flight_manager를 중복 실행하지 않는다.

## 실제 비행 결과와 남은 문제

같은 OMMPC와 반경 0.43m에서 160초 후 출발점 기준 목표 방향 진행은 기존 설정 약 1.13m, 새 실측 충돌체/팽창 설정 약 24.76m였다. 이동 구간 추종 RMS는 각각 약 5.76cm / 3.39cm였다. 단일 비교이며 지도 추정·경로·초기화에도 차이가 있으므로 일반적인 개선율로 해석하지 않는다.

새 설정도 전체 왕복은 실패했다. 회랑 생성의 비정상 수치/최적화 실패가 반복됐고, 이후 LIO/PX4 피드백 수신이 약 0.25초 끊겨 보호 착륙했다. 보호 전에는 나무 접촉 보고 0회, 독립적인 나무 표면 거리 하한 0.459m였다. 착륙 중에는 접촉이 발생했으므로 전체 trial은 FAIL이다. 기본 보호 임계값을 늘리지 않았다.

따라서 **기체 치수는 맞고, 원통의 형상 여유와 거친 지도 팽창은 과보수적인 부분이 확인됐다.** 경로 A/B 전환, 회랑 수치 실패 및 입력 지연까지 모두 해결됐다는 뜻은 아니다. 실측형상·세밀한 팽창은 실험 옵션으로 남긴다. 더 작은 계획 반경을 쓰려면 현재 IMU 기준점을 유지한 외접 반경·추종 여유를 다시 검증하거나, 전체 오도메트리/목표/제어의 기준점을 body로 일관되게 옮겨야 한다.

경로 유지 옵션 `--route-memory`는 별도 파일을 생성하며 기본값은 꺼져 있다. 기존 가지를 현재 지도에서 재검사해 안전하면 이어 쓰고, 회랑/최적화 실패 또는 장애물이 있으면 다시 탐색하도록 구현했고 단위 시험을 통과했다. 현재 기록에는 옵션을 켠 실비행 비교가 아직 없다. 팽창 시험에는 이 옵션을 섞지 않았다.


사용자 후속 설명: 이전 약 0.25초 입력 지연은 collision 확인 표시를 켜 연산 부하를 발생시킨 상황이었다. 해당 지연을 OMMPC 또는 팽창 설정 자체의 성능 결함 근거로 해석하지 않는다. 실제 중단·착륙·접촉 기록은 보존한다.


## 0.2m 추가 실험

사용자 요청으로 `--inflation-radius 0.2`를 추가하고 실제 동일 파이프라인에서 실행했다. IMU 기준 계획 반경은 0.43m로 유지했다. A*의 seed가 장애물에서 0.41231m인 경로를 반복 선택해 CIRI가 97회 거절했고, 원본 편도 목표로 출발하지 못했다. 입력 지연 중단이나 나무 접촉 없이 출발점에서 정상 착륙했다. [기록과 재현 명령](validation/zav-inflation02-20261105/README.md).
