# 이전 구현의 실험 기록

이 문서는 복도·층별 정책을 제거하기 전 버전의 동작과 시험을 기록한다. 현재 구현은 패키지 README를 참조한다.

이 변경은 EPIC의 탐색 목표 선택과 경로 계산에 적용한다. SUPER의 비용, 동역학 한계와 `common.yaml`은 변경하지 않는다. 건물별 좌표, 층수, 사전 지정 방문 순서는 탐색 입력으로 사용하지 않는다.

## 동작

- **표면 관측 완료:** 실제 LiDAR 반사점의 격자와 관측 방향을 기록한다. 신뢰 거리 이내에서 서로 다른 스캔 4회와 격자 두 칸 이상의 관측 위치 변화가 확인된 면은 같은 관측 작업으로 다시 만들지 않는다. 얇은 벽의 반대쪽 면은 별도 작업이다. 포인트맵의 장애물이나 원본 표면 라벨은 삭제하지 않는다.
- **빈 공간 확인:** 합성 통로·상승 후보의 이득은 장애물에 가리지 않은 광선에서 국소 3차원 미관측 덩어리가 확인될 때 인정한다. 직선 광선 위의 연속 길이만 보지 않고 코너를 돌아 연결된 공간도 검사한다. 격자 세 칸 반경에서 최대 96개 셀을 살펴보며, 12개 이상의 연결된 미관측 셀과 세 축의 두께·두 축의 폭을 요구한다. 이 검사는 정보 이득을 판정하며 미관측 공간으로의 비행을 허가하지 않는다. 한 칸짜리 샘플링 구멍만으로 복귀·상승 작업을 만들지 않는다. 아래층의 실제 경로를 현재 높이에 투영해 얻은 통로 후보도 같은 이득·반복 방문 검사를 거친다. 위치를 다른 높이에 투영했다는 이유만으로 새 탐색 작업으로 인정하지 않는다. 이 검사는 후보의 이득에 적용하며 이미 관측한 자유공간을 통과 불가로 바꾸지 않는다.
- **반복 방문 억제:** 합성 목표에 실제로 두 번 접근했는데 주변 자유공간 증거가 늘지 않으면 같은 작업을 보류한다. 새 증거가 생기면 다시 선택할 수 있다. 제자리 경로 재발행은 방문으로 세지 않으며 높이가 다른 작업은 분리한다.
- **층별 전략의 적용 범위:** 실측 장애물과 자유공간에서 현재 위치 아래에 충분한 바닥 지지가 확인될 때 층별 후보 제한과 출입구 복귀를 적용한다. 선반 옆 공중에 있다고 새 층으로 가정하지 않는다. 출입구에 실제 남은 관측 이득이나 상승 통로가 없으면 복귀를 강제하지 않는다. 같은 높이의 보조 복귀는 완료 후 반복하지 않는다. 원래의 3차원 연결 그래프는 유지한다.
- **시간 비용:** 관측점 간 비용은 현재 속도, 경로의 회전과 EPIC에 기존 설정된 속도·가속도·저크 모델로 추정한 이동 시간을 사용한다. 이는 상위 방문 순서의 비용 모델이며 외부 SUPER가 실제로 실행하는 시간과 정확히 같다는 뜻은 아니다. SUPER의 실행 제한값을 변경하지 않는다. 짧은 거리만으로 급회전과 방향 전환이 싼 경로가 되지 않게 한다.
- **계산 비용:** 동일 스캔의 표면 완료 판정과 거리 질의를 재사용한다. 거리의 Lipschitz 경계나 기존 bubble 겹침 규칙으로 같은 결과가 증명되는 경우만 충돌 질의를 생략한다. 관측된 전방으로 부분 경로를 찾을 때는 목적함수의 하한에 근접한 해를 찾으면 제한된 격자 전체를 소진하지 않는다. 최종 경로의 관측·여유거리 검사는 유지한다.
- **입력 상태 최신성:** Isaac 외부 플래너 연결은 원본 IMU 측정 시각과 현재 body odom 측정 시각을 직접 비교한다. 기본 `external_reference_imu_topic`은 `/drone0/mid360/imu`다. 위치나 자세의 ground truth는 사용하지 않는다. LIO adapter가 `/clock`도 발행하므로 둘이 함께 지연되면 시계·odom 차이만으로는 지연을 발견할 수 없기 때문이다. `exploration.state_max_age=0.10`초를 적용하고 첫 경로 전에는 `exploration.startup_freshness_confirmation=0.5`초와 세 번 이상의 새 상태값을 요구한다. 같은 오래된 표본의 재수신은 확인 횟수를 늘리지 않는다. 출발 전과 비행 중 모두 입력이 늦으면 무거운 지도·전역 계획 처리를 미뤄 추정기가 따라잡도록 한다. 첫 경로는 계산 후에도 최신 상태로 확인·연결한 뒤 보낸다. 원본 IMU 기준을 설정했는데 메시지가 없으면 ROS clock으로 몰래 대체하지 않는다. 센서와 odom 시각은 같은 epoch여야 한다. 독립 센서 기준이 없는 외부 시스템은 launch 인자를 빈 문자열로 지정해 ROS clock 비교를 명시적으로 선택할 수 있다.
- **이동 중 방향 전달:** 출발점의 실제 yaw에서 관측 yaw까지 짧은 각도 방향으로 보간한다. 수평 경로는 현재 속도와 기존 EPIC 속도·yaw 속도 모델로 회전 구간 길이를 정하고, 긴 복도 끝까지 방향 정렬이 미뤄지지 않도록 한다. 계단은 기존의 경로 길이에 따른 보간을 유지한다. 필요한 U턴의 접선 방향 처리와 최종 관측 방향도 유지한다. 이는 실제 yaw 속도를 강제로 제한하는 제어기가 아니라 상위 방향 참조의 생성 방식이다.
- **출발 참조 확대:** 첫 2초의 측정 시간 동안 위치 참조 길이는 여유거리의 0.5배로 제한하고 측정 yaw를 유지한다. 이어지는 2초 동안 길이를 여유거리의 1.5배까지, yaw 참조 차이를 0.30rad까지 점진적으로 늘린다. 이 출발 구간에도 최신 상태를 확인한다. 국소 제어기의 최대 속도·가속도·저크 한계를 낮추는 방식은 아니다.
- **첫 제어 인계:** 첫 짧은 경로를 실제로 발행한 뒤 `exploration.control_handoff_quiet_time=3.0`초의 센서 시간 동안 새 전역 경로 발행과 무거운 지도·전역 계획 처리를 보류한다. 원본 IMU와 body 상태 수신, SUPER·OMMPC·센서 동작은 유지한다. 의도적으로 짧게 자른 초기 경로가 일반적인 끝점 연장 로직을 계속 자극하여 국소 계획 시작과 겹치지 않게 한다. 이 절차는 첫 인계에 한 번만 적용하며 계단·복도 경유점마다 반복하지 않는다.
- **첫 방향 정렬:** 첫 관측 방향과 기체 방향이 1rad 이상 다르면 EPIC이 보내는 yaw 차이를 0.30rad 이내로 제한하고, 위치 경로는 여유거리의 1.5배 길이로 먼저 전달한다. 실제 방향 차이가 0.5rad 이내가 되면 전체 전방 경로 전달로 돌아간다. 원래 탐색 목표는 유지하며 정렬 완료 후의 코너·계단 경유점에는 이 출발 제한을 다시 걸지 않는다. SUPER의 yaw 최적화나 비행 제한값을 변경하지 않는다.
- **병렬 관측 조회:** 여러 cluster의 관측점 점수가 병렬로 계산될 때 공용 표면 완료 캐시의 읽기·삽입을 동기화한다. 원래의 관측 증거 계산은 잠금 밖에서 수행하며 동일 스캔의 캐시 초기화는 병렬 작업이 끝난 뒤 수행한다. 4개 스레드의 동시 질의가 순차 계산과 같은 값을 내는 회귀 검사도 포함한다.
- **CPU 공유:** 시작 시 `exploration.planning_workers`를 지정하면 EPIC의 병렬 루프에 공통으로 적용한다. 생략하면 그래프 갱신은 2개, 후보 생성과 경로 비용 계산은 단계에 따라 4개 또는 6개를 사용한다. 각 값의 상한은 사용 가능한 논리 CPU 수다. Isaac용 EPIC launch는 OpenMP 대기 정책을 `PASSIVE`로 설정한다. 외부 SUPER 연결 시 EPIC 프로세스만 `nice -n 10`으로 실행해 나중에 생성되는 작업 스레드에도 낮은 계산 우선순위가 상속되도록 한다. 센서·제어 처리와 경쟁하는 계산 스레드를 줄이기 위한 설정이며 제어기의 센서 시간 제한을 완화하지 않는다.
- **종료 경로 전달:** 원래 경로의 각 변을 균등하게 나누어 코너·목적지를 유지하면서 인위적인 1cm 끝 구간이 생기는 것을 피한다. EPIC이 완료를 판정한 뒤에도 현재 경로를 유지하다가 최신 측정에서 속도 0.15m/s 미만이 0.5초 동안 확인되면 현재 위치에서 끝나는 짧은 정지 경로를 한 번 보낸다. 외부 추종기가 이전 경로를 정리하도록 하는 절차이며 SUPER의 마지막 구간·도착·정지 조건을 완화하지 않는다. 움직이는 기체를 정지 궤적으로 잘라 바꾸지 않는다.
- **완료 확인:** 미관측 후보가 사라졌다는 확인 시간은 새 센서 스캔의 시간으로 센다. 한 번의 오래된 스캔을 오래 계산했다는 이유로 탐색 완료가 되지 않는다.

## 한계

미지 환경에서 전역 최단시간을 보장하는 알고리즘은 아니다. 앞으로 드러날 연결 관계를 미리 알 수 없고 비행 가능성·관측 품질·계산 시간 사이의 선택이 필요하다. 목표는 같은 파라미터로 불필요한 재방문과 지연을 줄이면서 실제로 관측 가능한 영역을 탐색하는 것이다. 닫힌 방, 기체가 통과하지 못하는 구멍, 센서로 볼 수 없는 영역의 완전 탐색은 보장하지 않는다. 지도 범위와 센서·기체 설정은 실제 운용 범위를 포함해야 한다.

관측 완료는 신뢰 거리, 스캔 수와 관측 위치 변화에 대한 조건이며 고해상도 표면 복원을 보장하지 않는다. 스캔 수는 통계적으로 독립인 관측 수를 의미하지 않는다. 부분 경로 검색의 조기 종료는 같은 장애물 검사를 유지하지만 경로 선택 자체는 기존의 전체 격자 탐색과 다를 수 있다.

## 검증

`corridor_pass_test`, `goal_handoff_test`, `surface_visibility_test`에 반복 목표의 실제 도달·증거 증가, 바닥 지지, 방향별 표면 관측, 거리 질의 재사용, 부분 경로 하한, 센서 시간 기반 완료 조건의 회귀 사례가 있다. 기존 군집과 궤적 적분 테스트도 함께 실행한다.

실제 비행 시험에서는 플래너의 FINISH와 별도로 물리 위치, TRACKING 중의 충돌 이벤트, 제어 오류, 센서 관측 범위를 확인한다. 시뮬레이션 시간과 실제 경과 시간은 구분한다. 단순 장면의 알려진 형상은 오프라인 검증에만 사용하며 플래너에 전달하지 않는다. 상세 시험 결과는 작업 공간의 `log/epic-general-20261120`에 저장한다.

### 접촉 기록의 판정

독립 검증기는 탐색 중 native PhysX의 각 접촉점에서 최소 separation과 최대 impulse를 검사한다. 양수 separation이 2cm를 넘고 impulse가 없는 기록은 떨어진 형상 간의 근접 알림으로 분리한다. 2cm 이내, 관통, 충격이 있거나 유효한 점 정보가 없는 found 이벤트는 보수적으로 접촉으로 센다. 점 정보가 없는 lost 이벤트는 접촉 해제다. coalesced persist 기록도 검사하며 원본 알림 수, 최소 거리, callback 오류·유실을 함께 남긴다. 보고된 범위 안에서의 검사이며 센서 지도만 보고 충돌 여부를 판단하지 않는다.

### 상태 지연 통합 검사

```bash
source simulator/ros_setup.sh
ctest --test-dir build/epic_ros2 --output-on-failure
python3 src/epic_ros2/test/integration/startup_freshness.py --output /tmp/epic-freshness-check
```

통합 검사는 별도의 ROS domain 139에서 실행하며 다른 노드가 있으면 중단한다. 합성 원본 IMU는 현재 시각을 보내되 adapter clock과 odom을 함께 0.56초 늦추어, 서로 같은 지연이 최신 정보로 오인되지 않는지 검사한다. 정상 측정 시각으로 복구되면 경로가 발행되는지도 검사한다. 실제 PX4나 SUPER는 실행하지 않는다. 이 검사를 통과했다고 실제 기체의 자세 추종까지 검증한 것은 아니다.

### 단순 형상 장면 재생성

```bash
python3 src/epic_ros2/test/integration/make_scenes.py --output-dir /tmp/epic-scenes
# 터미널 1: 아래 loop를 다른 생성 장면 이름으로 바꿀 수 있다.
ZAV_SUPER_TERRAIN_USD=/tmp/epic-scenes/loop.usda ./run_super_sim.sh frontier
# 터미널 2: 시뮬레이터 준비 후
./run_super.sh --scenario frontier --route-source epic --execute
```

생성 장면은 순환 통로, 막다른 방, 서로 다른 폭의 복수 출입구, 높은 선반, 경사로와 중층 플랫폼, 경사로를 통해서만 상층에 들어갈 수 있는 복층 통로다. `frontier` 시나리오는 이 시험에서 센서·이륙·EPIC 실행 연결에 사용하며 실제 지형은 환경변수로 교체한다. 이 결과를 Frontier 실사맵 시험으로 세지 않는다. 이륙 위치는 기존 Frontier 설정과 같은 열린 영역에 놓인다. 장면을 바꿀 때 이전 실행을 종료하고 새 시뮬레이터를 시작한다.
